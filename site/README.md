# Сайт «Глоссалия»

Сайт показывает выбранные материалы [Glossolalia Explorer](https://github.com/hayOfLife/glossalia-explorer). Основной адрес — [glossalia-explorer.tuqo.ru](https://glossalia-explorer.tuqo.ru/). Исходная оболочка находится в `site/public_html/`, готовые для Tuqo статические страницы собираются в `site/build/`; исходный снимок записей находится в `site/public_html/data/entries.json`, а данные фильтра транскрипций — в `site/public_html/data/calendar-transcriptions.json`.

- В разделе «Новые транскрипции» (`/calendar/`) форма фильтрует транскрипции по диапазону дат и ежедневному диапазону времени включительно. По умолчанию обе даты равны текущему дню в `Europe/Moscow`, часы — `00:00`–`23:59`. Флажок «Все даты» отключает поля дат и позволяет искать по всем опубликованным транскрипциям; записи без известной даты доступны только в этом режиме. Записи без известного времени показываются только при полном диапазоне `00:00`–`23:59`. Если начало диапазона даты или времени позже конца, форма показывает ошибку.
- Поиск слова или фразы в транскрипции ищет буквальное совпадение без учёта регистра в полном исходном тексте и тексте карточки для копирования; переводы и разборы в этот поиск не входят. Отдельное поле ищет таким же способом по назначению. Оба поиска применяются совместно с датами, временем и фильтром «Разбор транскрипции»: «Все» (по умолчанию), «Проценты» с включительным диапазоном от 0 до 100 или «Словесная метка» с выбором отображаемой метки «авто» или «не требуется». Ручной разбор соответствует 100%, процентная метка — указанному числу. Результаты сохраняют обычные раскрывающиеся карточки с назначением, полем копирования, меткой разбора, предполагаемым переводом, кнопками «Скопировать» и «Подробнее», оценками и скрытым чатом. ## Структура

- `public_html/` — единственный каталог, который должен быть доступен посетителям.
- `public_html/data/entries.json` — опубликованный снимок записей для браузера.
- `public_html/data/calendar-transcriptions.json` — данные всех опубликованных источников транскрипций для фильтра: исходная запись `entry`, полный исходный текст `originalText`, текст для копирования, назначение (`purposeText` и `purposeHtml`), перевод и адрес подробного разбора. `purposeText` содержит обычный текст того же назначения, которое отображает `purposeHtml`; содержимое карточек совпадает с отдельными страницами тех же источников.
- `calendar-index.json` — список уже учтённых файлов транскрипций; новые файлы сравниваются с ним.
- `scripts/update_calendar.py` — генератор календарных карточек из новых Markdown-файлов.
- `database/schema.sql` — схема MySQL 5.7.
- `database/seed.json` — начальные шесть записей, извлечённые из публичных карточек репозитория.
- `database/config.example.php` — образец параметров БД без учётных данных.
- `scripts/import.php` — однократный импорт начальных записей в пустую таблицу.
- `scripts/publish.php` — создание нового снимка из опубликованных записей БД.

## Поисковый заголовок и описание

Для `/translation/` утверждённые автором поисковые метаданные заданы в открывающем теге панели `translation` в `public_html/index.html`: `data-page-title` содержит полный заголовок, `data-description` — описание. Сборщик использует их в `<title>`, `description` и соответствующих Open Graph-тегах без добавления бренда к полному заголовку или обрезки заданного описания. Браузер сохраняет тот же заголовок после запуска JavaScript и переключения панели. Для остальных страниц действуют прежние правила автоматического формирования метаданных.

После изменения этих атрибутов пересоберите сайт. Локальная сборка подготавливает файлы; для обновления поисковых данных нужны публикация сайта и последующий обход страницы роботом.

## Новости

Новости страницы `/news/` хранятся в `public_html/data/entries.json` с типом `news`. Дата новости обозначает дату публикации; для первого сообщения автора об архиве промпта Алисы указано 05.10.2026. Поле `bodyText` поддерживает Markdown-ссылки, например `[перевод](https://glossalia-explorer.tuqo.ru/translation/)`: клиентский код создаёт безопасные DOM-ссылки только для новостей, не вставляя произвольный HTML.

Сборщик включает текст новостей и ссылки прямо в `site/build/news/index.html`, поэтому они доступны без JavaScript. Ссылки `/translation/` и `/data/translation_materials.zip` используют корень текущего сайта: раздел перевода и архив открываются по одному правилу в локальной сборке и после публикации на основном сайте. Новости не получают разбор транскрипции, голосование или скрытый чат. Подготовка локальной сборки не означает её публикацию на Tuqo.

Счётчик `113419573` подключён через внешний файл `public_html/assets/metrika.js`. Он загружает код Метрики только при `location.hostname === "glossalia-explorer.tuqo.ru"`: на локальном сайте и других доменах JavaScript не создаёт счётчик и не отправляет статистику. CSP разрешает адреса Метрики и Вебвизора для скриптов, запросов и кадров; встроенный исполняемый код не требуется. Статистика собирается только при включённом JavaScript: картинка `noscript` отсутствует, поскольку общая статическая сборка используется и локально, а без JavaScript проверка домена не выполняется.

Включены Вебвизор, карта кликов, отслеживание ссылок и точный показатель отказов; для электронной коммерции задано имя `dataLayer`. В оболочке со сменой раздела через `hashchange` вызывается `hit` после обновления заголовка страницы; раскрытие абзаца и переход к обычному якорю нового просмотра не создают.

Скрытые чаты и окна владельца помечены `ym-hide-content`, а поля сообщений и пароля — `ym-disable-keys`, чтобы исключить их содержимое и ввод из записи Вебвизора. Подготовка локальных файлов не означает публикацию счётчика на Tuqo.

Они проверяют код счётчика в изолированном окружении, не отправляют статистику и не подтверждают поступление данных в кабинет Метрики. ## Оценки транскрипций

Tuqo раздаёт только статические файлы. Общие счётчики ведёт отдельный HTTPS API на VPS. Серверный процесс и его файл голосов отделены от публичных файлов сайта. Исходники API пока не отправлены в GitHub; эта страница описывает действующее размещение, а не инструкцию по его воспроизведению из текущего коммита.

Публичный API проверен тестовым голосом со снятием; после проверки счётчик вернулся к исходному значению. Для посетителей голосование появится после отдельной публикации подготовленных статических файлов на Tuqo. Никакие ключи или пароли в браузерный код и Git не добавляются.

Голос привязан к случайному идентификатору в браузере, а не к человеку: очистка хранилища или другой браузер позволяют проголосовать снова. На сервере сохраняется только SHA-256 этого идентификатора и выбор лайк/дизлайк. API ограничивает изменения голосов до 12 за 10 минут для идентификатора и 40 за 10 минут для IP; посетители за одним IP делят общий лимит. IP и счётчики лимитов хранятся только в памяти процесса и сбрасываются при его перезапуске. Эти ограничения замедляют накрутку, но не исключают её полностью.

Изменение от 30.09.2026 подготовлено в статической сборке: голосование есть у всех опубликованных транскрипций в календаре, заполненных раскрывающихся блоках и на отдельных страницах. Повторное отображение одного источника использует общий `reactionKey`; новости, страницы ситуаций без транскрипций, словарь и пустые блоки голосования не получают. Прежние ключи и накопленные голоса сохраняются.

Для локального просмотра и опубликованного сайта предусмотрены два экземпляра API. Браузер определяет локальную версию по `location.hostname`: `localhost`, `127.0.0.1` или `[::1]`. Она обращается к `https://94-232-41-163.sslip.io/glossaliae/reactions-local`, остальные адреса — к прежнему `https://94-232-41-163.sslip.io/glossaliae/reactions`. Режим нельзя переключить параметром страницы. CSP разрешает оба точных адреса API.

Боевой экземпляр по умолчанию работает в режиме `production` на порту 8791, принимает изменения только от `https://glossalia-explorer.tuqo.ru` и сохраняет прежний файл `/var/lib/glossaliae-reactions/reactions.json`. Служба [локального экземпляра](reactions-api/deploy/glossaliae-reactions-local.service) задаёт `REACTIONS_ENVIRONMENT=local`, порт 8792 и отдельный файл `/var/lib/glossaliae-reactions-local/reactions.json`; у неё отдельный системный пользователь. Локальный API разрешает только канонические HTTP/HTTPS Origin с тремя перечисленными адресами и корректным портом. Другие IP, поддомены `localhost`, `null` и запросы с боевого сайта не получают разрешения на изменение локальных голосов. Caddy передаёт запросы через [отдельный маршрут](reactions-api/deploy/Caddy-local-route.caddy), не открывая порт 8792 наружу.

Идентификатор браузера, сохранённый выбор и лимиты IP/ID разделены по средам. Локальная версия использует ключи `glossaliae-voter-id-local` и `glossaliae-votes-local`; боевые ключи остаются прежними. Одинаковая транскрипция и тот же браузер могут иметь разные оценки в двух средах. Очистка локального файла или исчерпание локального лимита не меняет боевые данные. Проверка Origin отделяет обычные запросы браузеров, но не является аутентификацией: самостоятельный HTTP-клиент может подставить заголовок Origin; прежние ограничения накрутки продолжают действовать отдельно в каждой среде.

Для добавления локальной среды к уже установленному API используется [сценарий](reactions-api/deploy/enable-local-environment.sh). Он требует временный каталог с проверенными файлами и SHA-256 действующего сервера и Caddyfile, проверяет сохранённое хранилище без записи и создаёт закрытые резервные копии конфигурации. При ошибке восстанавливает код и конфигурацию, сохраняя файлы голосов. У Caddy на этом VPS задано `admin off`, поэтому изменения применяются через restart службы. Оставшийся после остановленной установки локальный каталог можно использовать только с явным аргументом `resume-local-state` после проверки его расположения и содержимого.

Весь чат, включая форму, технические правила и переданный автором дисклеймер, имеет атрибут `hidden`. Удаление этого атрибута в инструментах разработчика включает чтение и форму. Сервер случайно назначает уникальный для всех чатов псевдоним: `user` и 12 латинских букв и цифр. Имя не вычисляется из токена; сервер хранит его связь с SHA-256 секретного токена отправителя. Один токен сохраняет тот же псевдоним во всех чатах и после перезапуска; произвольное имя при записи не принимается. Хеш и сам токен не возвращаются клиентам. Обе версии сайта читают и записывают комментарии через `https://94-232-41-163.sslip.io/glossaliae/comments`. Разделение локальных и боевых лайков сохраняется. Боевой процесс хранит сообщения и таблицу пользователей в отдельном `comments.json` рядом с приватным `reactions.json`; публичная сборка и Git не содержат этих файлов. Расширение обращений к автору использует версию 3 с ролью сообщений владельца и таблицей `inboxRead`; предел остаётся 8 MiB и по 10 000 сообщений и пользователей. Версии 1 и 2 читаются без перезаписи и преобразуются при следующем успешном изменении, сохраняющем ID и имена версии 2. До сохранения версии 1 новые случайные имена ещё не закреплены на диске. Повреждение файла комментариев закрывает комментарии для записи и не блокирует голосование. Ответы связываются идентификаторами внутри одного чата; можно отвечать себе и другим участникам, переходить к исходному сообщению и загружать более старые сообщения. Старый модуль версии 2 не читает версию 3: перед возвратом прежнего кода нужно проверить совместимость текущего файла, не теряя новые сообщения.

Сообщение ограничено 2000 символами Unicode. Сервер проверяет пустой текст, явные отдельные ругательства на русском и английском и повтор нормализованного текста среди двух предыдущих сообщений: окно из трёх включает новое сообщение. Проверка повтора действует для чата, ключа отправителя и адреса клиента; правка существующего сообщения также проверяется. Между успешными записями с одного адреса или ключа требуется 10 секунд. За 10 минут допускается 8 попыток записи на ключ отправителя и 20 на IP; редактирование входит в лимиты. Для административных изменений есть отдельные 20 попыток на IP, для чтения состояния и обращений — 100; перед чтением тела действует общий предел 200 попыток на IP. Опрос колокольчика не расходует лимит административных изменений. Эти ограничения затрудняют спам, но смена сети и ключа не даёт гарантированного определения человека. Адрес для ограничений передаёт Caddy, перезаписывая `X-Glossaliae-Client-IP`.

Секретный токен отправителя создаётся в его браузере: 32 криптографически случайных байта в виде 64 строчных шестнадцатеричных символов, сохранённых в `localStorage` под ключом `glossaliae-comment-author`, отдельно от идентификатора лайков. Сервер сохраняет только SHA-256 токена. Токен позволяет редактировать свои сообщения в течение первых пяти минут по времени сервера; он не возвращается в публичном JSON и не помещается в URL. Сохранённый токен можно повторно использовать прямым клиентом. Потеря токена означает новый псевдоним и потерю доступа к прежним правкам; знание чужого токена позволяет писать от этого пользователя. Текст и псевдонимы отображаются как обычный текст; HTML и скрипты из сообщений не выполняются.

Управление владельца появляется только на локальной странице «для ИИ (for AI)». При попытке управления открывается модальное окно пароля. Сервер сверяет пароль с `COMMENTS_ADMIN_PASSWORD_HASH` из приватной конфигурации боевой службы: формат `scrypt$СОЛЬ$ХЕШ`, соль — 16 случайных байтов, хеш — 64 байта, оба в шестнадцатеричной записи; параметры scrypt — N=16384, r=8, p=1. Исходный пароль не хранится на сервере или в браузере и не включается в HTML, архив, Git либо журналы. Без настроенного хеша управление отключено; обычные комментарии остаются доступны.

После входа сервер выдаёт случайный токен сессии на 30 минут. Локальная вкладка сохраняет только этот токен и срок в `sessionStorage`, очищает их при выходе или истечении срока. Перезапуск API также завершает сессии; при следующем действии снова появляется окно пароля. Белый IP не требуется. Вход ограничен пятью попытками на IP за 10 минут, отдельно от административного лимита; длина пароля — до 256 символов Unicode и 1024 байтов UTF-8. Боевой unit читает необязательный `/etc/glossaliae-reactions/comments-admin.env`: приватный файл с хешем принадлежит root с правами `0600` и не передаётся локальному экземпляру оценок.

Владелец может закрыть создание сообщений в одном чате или во всех, затем снова открыть запись. Чтение и правка уже отправленного своего сообщения в пределах пяти минут остаются доступны. При удалении из сообщения стираются имя, текст и хеш токена отправителя; остаётся отметка удаления с идентификатором для уже существующих ответов. Связь хеша токена с псевдонимом в таблице пользователей сохраняется, чтобы следующие сообщения получили прежнее имя. Административные POST-запросы разрешены только от канонических локальных Origin и с действующей сессией. Проверка Origin сама по себе не заменяет сессию: произвольный HTTP-клиент может подставить этот заголовок.

Контракт: публичный `GET ?key=КЛЮЧ` возвращает последние 50 сообщений, `before=ID` — предыдущую страницу, `id=ID` — конкретное сообщение того же чата. Запись идёт POST с `Content-Type: text/plain;charset=UTF-8`: `create` принимает ровно `action`, `key`, `text`, `authorToken`, `replyTo`; `edit` — `action`, `key`, `id`, `text`, `authorToken`. `replyTo` равен `null`, ID сообщения этого чата или специальному адресату `"user_001"`. `admin-login` с `key: "*"` передаёт `password` и возвращает `adminToken` со сроком `expiresAt`; `admin-status`, `admin-lock` и `admin-delete` передают этот `adminToken`. Ответы входа, состояния и закрытия содержат `discussionKeys` со всеми разрешёнными чатами и `unreadCount` с числом непросмотренных обращений. Пароль проверяется без преобразования регистра и Unicode. Полный шаблон формы и технические правила для прямого клиента находятся в скрытом HTML; сервер принимает только точные наборы полей.

Чтобы написать автору, используйте скрытую кнопку «Написать автору» или добавьте `replyTo: "user_001"` к запросу `create`. Сообщение остаётся в выбранном чате и попадает в общий список обращений. После входа владельца на локальной странице для ИИ появляется колокольчик с числом непросмотренных сообщений; окно позволяет просматривать каждое отдельно, отметить «Просмотрено», открыть поле ответа с кнопками «Ответить»/«Отмена» и удалить сообщение. Отметки сохраняются на сервере; открытие окна и отправка ответа не отмечают сообщение автоматически. Правка просмотренного обращения делает его непросмотренным. Ответ владельца публикуется в исходном чате как `user_001`; посетительский ответ на него тоже попадает в список обращений. Закрытая запись для посетителей не запрещает ответ владельца. Список включает и просмотренные сообщения, удалённые исключаются.

Административные запросы обращений используют прежнюю сессию и локальный Origin:

| Действие | Поля помимо `action` и `adminToken` | Ответ |
| --- | --- | --- |
| `admin-inbox` | `key: "*"`, необязательный `before: ID` | `messages` с дополнительными `key`/`read`, `nextBefore`, `unreadCount`, `serverTime`, `limits`; последние 50 обращений по возрастанию времени, затем более старые страницы |
| `admin-read` | `key: КЛЮЧ`, `id: ID`, `updatedAt: ВРЕМЯ_ПОКАЗАННОЙ_ВЕРСИИ` | `unreadCount`, `serverTime`, `limits`; если текст уже изменён — `409` с `error: "stale_message"` |
| `admin-reply` | `key: КЛЮЧ`, `id: ID`, `text: ТЕКСТ` | `message` с именем `user_001` и `replyTo: ID`, `unreadCount`, `serverTime`, `limits` |

Количество в колокольчике обновляется раз в минуту, пока локальная вкладка видима и сессия действует. Список и число учитывают действующие ключи чатов; данные снятых с публикации ключей сохраняются. Закрытие окна, выход и истечение сессии отменяют незавершённые операции интерфейса. Обращения не являются приватной перепиской: сообщения и ответы читаются через публичный API чата; список владельца и отметки прочтения требуют административной сессии. Причина выбора описана в [ADR-0010](../docs/architecture/decisions/0010-author-inbox.md).

Кнопка «Начать>» загружает [компактный промпт](public_html/data/promptForAlice_guessingTheMeaningOfTheGlossary.min.txt) и передаёт его Алисе AI. [Полный промпт](public_html/data/promptForAlice_guessingTheMeaningOfTheGlossary.txt) сохраняет присланный текст с отдельно запрошенными автором изменениями; сборщик автоматически создаёт компактную версию, удаляя только пустые строки и сохраняя текст остальных строк и пробелы внутри них. Ссылка «Скачать архив промпта» отдаёт `/data/translation_materials.zip`, который автоматически собирается из актуальных канонических источников при сборке сайта и содержит пять TXT. После первого ответа Алисы посетитель отправляет ручную транскрипцию отдельно.

В разделе «Дополнительная информация» основного промпта есть ссылка «Теория глоссалии (дополнительная информация)» на публичный MD-файл теории Алисы AI. Рядом находятся ссылки на страницы о звуках русского языка и иврита, латинских и греческих процессуальных системах и транскрипционных пометках. В TXT используются полные адреса сайта, чтобы ссылки работали из скачанного архива; на странице перевода те же адреса становятся относительными к текущему сайту для локального просмотра. Дополнительные документы не добавляются отдельными файлами в архив.

| Файл в ZIP | Канонический источник |
| --- | --- |
| `PROMPT_general.txt` | [Полный промпт](public_html/data/promptForAlice_guessingTheMeaningOfTheGlossary.txt) |
| `dictionary_of_words.txt` | Байты [метода составления словаря слов](../docs/dictionary/methodology.md), затем байты [словаря слов](../docs/dictionary/combined.md) |
| `dictionary_of_suffixes_and_particles.txt` | Байты [метода составления словаря суффиксов и частиц](../docs/dictionary/suffix-methodology.md), затем байты [словаря суффиксов и частиц](../docs/dictionary/suffixes.md) |
| `phonetics_rus_vs_hebrew.txt` | [Звуки которых нет в иврите но есть в Русском языке](<public_html/assets/documents/Звуки которых нет в иврите но есть в Русском языке.txt>) |
| `dictionary_of_abbreviations.txt` | Побайтная копия [таблицы сокращений канала](../docs/dictionary/abbreviations-source.txt) в формате Markdown внутри TXT |

Каждый присланный TXT словаря уже содержит свою методологию. Его разделяют перед вторым заголовком первого уровня на существующие файлы метода и словаря, сохраняя байты обеих частей. В ZIP словарные файлы снова составляются конкатенацией этих частей в исходном порядке, без добавленных разделителей. При первоначальной замене результат побайтно совпадает с присланным TXT; после отдельно запрошенных автором уточнений архив содержит актуальную каноническую редакцию словаря. Методы включены в словарные TXT; отдельные дубли методов в ZIP не добавляются. Промпт и фонетический файл передаются в ZIP без изменений байтов; прежние словарные статьи автоматически не подмешиваются в новые тексты.

Архив создаётся в `site/build/data/translation_materials.zip` с постоянными метаданными ZIP, поэтому неизменные источники дают одинаковый файл при повторной сборке. Для обновления редактируйте актуальные канонические файлы и пересобирайте сайт; отдельные копии для редактирования не создаются. По указанию автора приоритет имеют файлы промпта: сборщик читает их байты один раз и использует этот общий снимок для архива, полного главного промпта на странице перевода и отдельных страниц словарей. На `/translation/` словари представлены ссылками на эти страницы. Ручной сокращённой копии главного промпта нет. Сгенерированные HTML-фрагменты предназначены только для показа, их не редактируют.

### Как собрать архив промпта и словарей

В PowerShell перейдите в корень этого клона и запустите сборщик. Требуется Python в `PATH`; архив собирается стандартной библиотекой Python.

```powershell
Set-Location -LiteralPath 'C:\Users\User\Documents\ChatGPT\Проекты\glossolalia-explorer-site-publish'
python -B -X utf8 .\site\scripts\build_static.py
```

Команда пересобирает весь статический сайт и формирует ZIP из пяти файлов, собранных из канонических источников в таблице выше. Она обновляет `site/public_html/data/translation_materials.zip`, копирует его в `site/build/data/translation_materials.zip` и пересобирает остальные данные и манифест сайта. Успех — код 0 и сообщение «Собрано … разделов и … транскрипций»; ссылка `/data/translation_materials.zip` на странице перевода использует этот результат. Публикация на Tuqo выполняется отдельно вместе с готовыми файлами `site/build/`.

Для проверки состава, CRC и побайтного совпадения всех пяти файлов с источниками выполните из того же каталога:

```powershell
python -B -X utf8 .\site\tests\test_static_build.py StaticBuildTest.test_translation_download_archive_preserves_source_files
```

Успех проверки — один пройденный тест, сообщение `OK` и код 0. Тест читает готовую сборку, поэтому запускается после сборщика. Если команда `python` не найдена, укажите полный путь к установленному Python и вызовите его через `&`; если сборщик сообщает об отсутствующем исходнике, проверьте файлы из таблицы выше. После изменения промпта, метода, словаря или справочного документа снова выполните сборку: архив обновится автоматически.

## Локальный просмотр

Из корня репозитория в PowerShell при установленном Python запустите `python -B -X utf8 site/scripts/build_static.py`, затем `python -B -X utf8 site/scripts/serve_site.py` и откройте `http://127.0.0.1:8877/`. Первая команда записывает готовые файлы в `site/build/` и `site/content-manifest.json`, не удаляя другие файлы; вторая показывает готовый сайт локально и не меняет файлы. Сервер слушает только `127.0.0.1`, каталог по умолчанию — `site/build/`; доступны параметры `--port`, `--bind` и `--directory`. Текстовые ответы, включая Markdown и TXT, содержат `charset=utf-8`: без него браузер может ошибочно прочитать корректный UTF-8 как другую кодировку. Байты файлов и типы бинарных ответов не меняются. Остановка — `Ctrl+C`; если порт занят, остановите прежний локальный сервер или выберите другой порт через `--port`. Прямое открытие `index.html` как файла может заблокировать чтение JSON. Просмотр не проверяет доступность Tuqo либо API голосования.

Проверка заголовков и сохранности байтов локального сервера: `python -B -X utf8 site/tests/test_preview_server.py` из корня репозитория. Она создаёт временные файлы и HTTP-сервер на свободном порту localhost; успех — `OK` и код 0, внешние запросы не выполняются.

## Обновление сайта и данные

Tuqo нужно обновлять отдельно от GitHub. Архив для загрузки создавайте из содержимого `site/build/`: в корне должны быть `index.html`, `assets/`, `data/`, `sitemap.xml`, `robots.txt`, `content-manifest.json` и каталоги отдельных страниц. Каталоги `database/`, `scripts/` и серверный PHP-код не загружаются как публичные файлы.

Сборщик создаёт отдельные HTML-адреса для основных разделов и всех опубликованных разборов, указанных в календаре или на страницах сайта. Внешний вид основных разделов берётся из той же оболочки и CSS. Ссылки разделов ведут по обычным путям; старые адреса с `#` не поддерживаются. `sitemap.xml`, `robots.txt`, уникальные заголовки, описания, canonical-адреса и разметка `CreativeWork` для разборов формируются при сборке. Разбор читается прямо из исходного Markdown без изменения файла. Источник транскрипции в карточке указан как «автор», а ссылка на Markdown позволяет сверить опубликованный текст с GitHub.

Новые и изменяемые публичные пути страниц, документов и Markdown-представлений собственного сайта должны иметь английские названия и только ASCII-символы; кириллица и пробелы запрещены также в URL-кодированной форме. Подписи ссылок, текст документов и имя из атрибута `download` могут быть русскими. Ссылки на сторонние источники сохраняются дословно. При смене существующего адреса оставляйте совместимый старый путь; другие ранее опубликованные адреса с кириллицей переносятся отдельно по запросу автора. Это правило закреплено в [инструкциях проекта](../AGENTS.md).

После удаления общих копий от 11.10.2026 сохранены тематические владельцы: `docs/transcriptions/T00014.md` → [T00032/part_1](../docs/transcriptions/T00032/part_1.md), `T00028.md` → [T00027/part_5](../docs/transcriptions/T00027/part_5.md), `T00029.md` → [T00027/part_6](../docs/transcriptions/T00027/part_6.md), `T00032.md` → [T00032/part_2](../docs/transcriptions/T00032/part_2.md). Прежние HTML-адреса сайта открывают страницы перенаправления с canonical и ссылкой на тематический разбор; прежние Markdown-адреса сайта отдают короткие указатели. Это статическая совместимость, а не HTTP 301. Общие копии исключены из списков и sitemap; адреса совместимости не входят в sitemap. Прежние толкования первого скрипта добавлены к тематическому разбору, исторические контексты и датированные контрольные снимки сохранены. Удалённые исходные файлы на GitHub этими указателями не восстанавливаются.

Нумерованные списки Markdown отображаются отдельными пунктами с исходными номерами. В поле предполагаемого перевода и на полной странице разбора сохраняются вложенные пункты, в том числе когда сам список записан с отступом. Пустая строка цитаты `>` разделяет текст и не выводится как самостоятельный символ; исходный файл сохраняется. Блоки полного исходного текста сохраняют переносы строк, включая пустые строки, без добавления новых; HTML внутри них экранируется.

Обычный клик по «Подробно»/«Подробнее» или заголовку календарной транскрипции открывает полный разбор в окне поверх текущей страницы. Окно загружает текст с соответствующей статической HTML-страницы того же сайта; фон не прокручивается. «Закрыть» и Escape возвращают фокус к исходной ссылке и сохраняют место, параметры фильтра и раскрытые блоки. Адреса отдельных страниц остаются доступными поисковикам и по ссылке «Открыть отдельной страницей»; клики с Ctrl, Cmd или Shift сохраняют обычное поведение браузера. При отсутствии поддержки `dialog` работает исходная ссылка.

Обычные внутренние ссылки разделов, включая строки каталога и карточки справки, прокручивают новую страницу к верхним табам. Документы `/articles/`, «Евгеника vs генная инженерия» и «Взаимные претензии православных и протестантов» прокручиваются к своему заголовку. Целевой путь сохраняется в `sessionStorage` и проверяется при открытии страницы; переход к тому же разделу прокручивает сразу. При прямом открытии документа или открытии в новой вкладке прокрутка к заголовку работает без `sessionStorage`. Возврат через историю и перезагрузка сохраняют прежнее место, ссылки с якорями ведут к указанному фрагменту. Ссылки на полные разборы продолжают открывать описанное выше окно. Внешние ссылки и скачивание не запускают эту прокрутку. Если браузер запрещает `sessionStorage`, между отдельными HTML-страницами разделов работает обычный переход.

Все раскрывающиеся блоки используют «+» в закрытом состоянии и «−» в открытом. Выделение текста в полях копирования и подписи исходных слов в предполагаемом переводе имеют общий мягкий жёлтый цвет. Сборщик отмечает подписи в явных парах «слово → перевод» и в повторяющейся структуре «строка транскрипции, затем объяснение», сверяя структуру с исходной строкой. Полностью русский связный перевод и тексты исходных Markdown не меняются; написания подписей сохраняются, даже если в разборе они отличаются от исходной строки. Правила подсветки относятся только к отображению предполагаемого перевода.

Для новой карточки храните полную запись в разделе «Исходная транскрипция», а отдельное представление для чтения и копирования — в «Транскрипции для вывода». Если новый раздел вывода существует в каноническом Markdown, сборщик использует именно его, включая явно пустое значение, и не подменяет его прежним `copyText` или `textarea`. Для материалов без нового раздела сохраняется совместимость: `entries.json.copyText`, затем прежний раздел «Текст для копирования», существующий `textarea`, исходная транскрипция и, в последнюю очередь, календарный `bodyText`. Поле `bodyText` остаётся текстом календарной записи; исходная запись и версия для вывода не смешиваются.

Новые и уже приведённые к общему виду материалы используют [единый формат разбора](../docs/DOCUMENTATION.md#единый-формат-разбора), утверждённый автором после просмотра примера 11.10.2026; причина выбора — в [ADR-0013](../docs/architecture/decisions/0013-transcription-analysis-format.md). Полный набор заголовков, одинаковые разделители и правило маркера `⟐` определены в стандарте. Предоставленный автором отдельный вариант для вывода сохраняет свои слова; он не заменяется полной исходной строкой. Унификация оформления не разрешает менять слова транскрипции, содержание разборов, даты, назначения, авторство или статусы. Публичные представления создаются сборщиком из канонических файлов.

При новой записи ассистент применяет [правила добавления](../docs/DOCUMENTATION.md#добавление-новой-транскрипции): текущая отметка по Москве при отсутствии времени и другой явно указанной даты, самостоятельный предполагаемый тип, отдельные обстоятельства получения и допустимое назначение по контексту с атрибуцией ИИ. Явно указанная дата и неизвестный час исторического источника сохраняются; календарный генератор сам не датирует такие файлы текущим временем. Предполагаемое назначение, связный перевод, пословный разбор и краткое толкование должны оставаться различимыми. Если в материале есть результат модели, сохраняйте её название и экспериментальный статус; авторское толкование и прежние альтернативы сохраняйте с их авторством. Вывод модели и согласие автора сами по себе не подтверждают перевод. Отсутствующие необязательные блоки опускаются; исходные слова не восстанавливаются из толкования. История правок карточки пока не ведётся.

Быстрая проверка актуальности: сборка записывает SHA-256 исходных файлов в `site/content-manifest.json` и в архив сайта. Для текстовых файлов перед вычислением хеша окончания строк приводятся к LF, чтобы Windows и Linux давали одинаковый результат. После отправки манифеста в GitHub и публикации архива выполните `python -B -X utf8 site/scripts/check_site_sync.py` из корня репозитория. Скрипт скачает только два небольших манифеста — из GitHub и с сайта — и перечислит различающиеся файлы; он не скачивает все HTML-страницы. Совпадение манифестов подтверждает соответствие опубликованной сборки исходникам на момент её создания, но не выявляет последующую ручную замену отдельных HTML-файлов без изменения манифеста.

При добавлении нового файла в `docs/transcriptions/` укажите в нём поле `Дата и время получения транскрипции: ДД.ММ.ГГГГ, ЧЧ:ММ МСК` по правилам ассистента выше и раздел `## Исходная транскрипция` с дословным текстом; неизвестный час исторического источника можно опустить. Для прежнего авторского разбора генератор также понимает `**Дата:** 29 сентября 2026`, `## Исходная строка` и `## Необработанная транскрипция`; такая дата помечается датой разбора, а не установленным временем получения транскрипции. Из корня репозитория запустите `python -B -X utf8 site/scripts/update_calendar.py`: скрипт найдёт новые файлы, добавит записи в `public_html/data/entries.json` и запомнит обработанные пути в `calendar-index.json`. Он не изменяет исходные Markdown-файлы и останавливается с ошибкой, если не удаётся установить дату или исходную строку. Старые файлы без единого формата перечислены в индексе как уже учтённые; если нужно добавить один из них, передайте его путь скрипту явно.

При push новых файлов в `main` генератор календаря и сборщик страниц запускаются [GitHub Actions](../.github/workflows/calendar.yml). Автоматизация отправляет обновлённые JSON и манифест обратно в репозиторий. Для автоматической публикации на Tuqo нужен секрет репозитория `TUQO_API_KEY` с ключом проекта уровня `editor`; без него GitHub обновит исходники и манифест, но сайт останется на прежней версии. Никакие ключи в архив не включаются. Даты и известные часы сортируются по времени появления транскрипции; при неизвестном времени порядок записей внутри дня не утверждается.

Схема MySQL и скрипты импорта/публикации подготовлены, но текущий сайт не использует БД при открытии страниц. При отдельной настройке БД параметры доступа должны оставаться вне публичных файлов; обновлённый JSON-снимок публикуется на Tuqo только после проверки его содержимого. Проверка нагрузки для 100 одновременных посетителей ещё не проводилась.

Календарная дата хранится в БД как Unix timestamp в UTC для полуночи соответствующего дня по Москве. Такой timestamp служит ключом календарного дня и не обозначает время создания аудио.

## Все разборы транскрипций

Страница `/transcription-analyses/` (панель `article-transcription-analyses`) собирается из канонического [каталога разборов](../docs/TRANSCRIPTION_ANALYSES.md). Каталог содержит ссылки на существующие карточки и исходные файлы; полные тексты разборов в него не копируются. В пункте 9 «Дополнительная информация» главного промпта `PROMPT_general.txt` находится ссылка на эту страницу; основной файл архива и блок промпта на `/translation/` используют тот же текст.

Подпись каждой ссылки сохраняет раздел сайта, идентификатор транскрипции и часть или версию разбора. Номер `part_N` не подменяет номер абзаца на сайте: например, `T00027/part_10.md` соответствует одиннадцатому абзацу, а `T00032/part_1.md` относится к `T00014`. Дата получения берётся из карточки или уточнения автора; учётная дата, дата контекста и дата разбора сохраняют свои оговорки, неизвестные время и часовой пояс не дополняются. Исходные имена и порядок частей не меняются ради каталога.

При добавлении самостоятельного разбора или изменении его адреса обновляйте `docs/TRANSCRIPTION_ANALYSES.md` и пересобирайте сайт командой `python -B -X utf8 site/scripts/build_static.py` из корня репозитория.

## Метка способа разбора

В файле разбора хранится служебная строка `разбор транскрипции: авто`, `разбор транскрипции: ручной, 100%`, `разбор транскрипции: не требуется` или назначенная автором процентная метка, например `разбор транскрипции: 95%`. На сайте она отображается справа под полем для копирования как «Разбор транскрипции: авто», «Разбор транскрипции: 100%» или указанный процент. Допустимы целые проценты от 0 до 100 без ведущего нуля. В календарных карточках метка находится под текстом транскрипции. По уточнению автора от 12.10.2026 для понятного русскоязычного текста, которому перевод не нужен, используется «Разбор транскрипции: не требуется» и внутреннее значение `analysisMode: not_required`. Эта словесная метка доступна в фильтре, а в диапазоны процентов такая запись не входит. Это обозначение способа разбора, а не оценка достоверности перевода.

Метка в файле имеет приоритет. Если её ещё нет, сборщик выбирает `manual` при наличии «пометки автора» или слова «уточнено» без учёта регистра, иначе `auto`. При интеграции нового разбора добавляйте соответствующую строку перед исходным текстом, сохраняя все байты исходного тела. Для `docs/transcriptions/T00027/part_8.md` автор явно назначил `manual`. Ранее записанные хеши присланных файлов относятся к исходному телу без служебной строки и пустой строки после неё.

Сборщик обновляет `data/analysis-modes.json`, поле `analysisMode` календарных записей и метки HTML-страниц из исходных файлов. Служебная строка в тексте разбора на сайте не показывается; после изменения метки выполните обычную пересборку сайта.

## Значок способа получения транскрипции

Справа в заголовке каждого раскрывающегося абзаца с транскрипцией, в новых записях и на отдельной странице показывается небольшой значок: динамик для аудиозаписи, карандаш на бумаге для письменной записи. При наведении появляется пояснение. Способ получения хранится отдельно от метки разбора «авто / ручной».

Сборщик читает строку `- Способ получения транскрипции: аудиозапись` или `- Способ получения транскрипции: письменная запись` в Markdown-карточке и переносит значение в `acquisitionType` (`audio` / `written`) данных календаря. По уточнению автора от 03.10.2026 аудио назначено только T00001, T00002 и T00003; для остальных и для карточек без такой строки используется письменная запись. Упоминание модели внутри разбора не меняет значок. После изменения строки пересоберите сайт обычной командой из раздела обновления.

## Словари и методологии перевода

Только шапки сворачивающихся блоков используют светлый пастельный зелёный фон `#edf5e8` из переменной `--details-background` в `public_html/assets/styles.css`; содержимое сохраняет прежний фон. Общий стиль применяется также к вложенным словарям и динамическим карточкам календаря.

Раздел «Промпт для ИИ (тот-же что и в архиве выше)» на странице «Как сделать перевод иных языков» (`/translation/`) расположен после подсказки «Если чат не открылся с отправленным промптом…» и отделён толстой горизонтальной чертой. По умолчанию закрытый блок содержит полный главный промпт, отдельно раскрываемый фонетический справочник и карточки-ссылки на три словаря. Полные таблицы показываются на основных страницах: `/dictionaries/words/`, `/dictionaries/suffixes-and-particles/` и `/articles/channel-abbreviations/`. Методика каждого словаря находится над его таблицей. Карточки дополнительных документов остаются после общего блока. На странице «для ИИ (for AI)» остаются пять транскрипций и общий скрытый чат; её Markdown-обзор ссылается на страницу перевода и основные словари.

Словарь сокращений канала открывается через карточку внутри промпта сразу после фонетического справочника. Его основная страница — `/articles/channel-abbreviations/`. По уточнению автора от 06.10.2026 [канонический TXT](../docs/dictionary/abbreviations-source.txt) всегда содержит таблицу Markdown с пятью столбцами: «запись в транскрипции», «пример вхождения в транскрипцию», «полное слово», «заметка», «язык». Язык берётся только из явных указаний источника; несколько языков сохраняются вместе, а неизвестный язык не дополняется догадкой. Заметки сохраняют категории, контексты и статусы разных чтений. 08.10.2026 одинаковые частицы и сокращённые формы собраны здесь вместе с описаниями из прежних рабочих словарей; полные слова, оставленные в словаре слов, представлены ссылками на него. Число строк прежних редакций не является текущим размером таблицы. Присланный текст первоначально преобразован в 18 строк с сохранением всех пояснений и статусов; SHA-256 первоначального источника — `026D77F08A4582B8AB711E33D3D01D27DA29F25AE169C143924DA7A4810F9C42`, табличная редакция отличается от оригинала форматом. По таблице автора от 06.10.2026 были уточнены пять записей и добавлены девять, тогда итог составил 27 строк. Отсутствующие примеры остаются пустыми; категории и ограничения помещаются в заметках, общий методический раздел — после таблицы. Переносы внутри ячеек обозначаются `<br>`, вертикальная черта экранируется как `\|`; сборщик проверяет наличие таблицы и точные заголовки, проза вместо таблицы останавливает сборку.

07.10.2026 по последующему уточнению автора в категории «III. НЕ СОКРАЩЕНИЯ — ПОЛНЫЕ КОРОТКИЕ СЛОВА» перевод `Фа!` заменён на точный авторский текст «совершённый факт, уже факт»; сразу следом добавлена частица `фи` с переводом «на подходе, грядёт, в состоянии приближения», итог — 28 строк. Источник переводов — указание автора; независимая проверка не выполнена.

Позднее 07.10.2026 по прямому сообщению автора добавлены `form` → `formula` с примером `in*form`, `Шео` → `шеол` и `Деви` → `девил`; новый итог — 31 строка.

Главный промпт указывает зависимость от таблицы `dictionary_of_abbreviations.txt` и ссылку на её основную HTML-страницу `/articles/channel-abbreviations/` с кнопкой скачивания табличного TXT. Сборщик из одного снимка канонического файла создаёт таблицу на этой странице, публичный TXT `/data/dictionary_of_abbreviations.txt` и одноимённый пятый файл в ZIP. Генерируемые HTML-фрагменты не редактируют. Каноническая таблица и файл внутри ZIP совпадают побайтно; в готовой сборке `site/build/` публичный TXT получает маркер UTF-8 BOM для браузеров при отсутствии HTTP charset, байты после маркера совпадают с канонической таблицей. Для обновления меняют таблицу в каноническом TXT и пересобирают сайт.

Таблица на основной странице `/dictionaries/words/` строится из [объединённого словаря](../docs/dictionary/combined.md). Каждый заголовок `##` задаёт слово или сочетание. Шесть столбцов — «Написание», «транскрипция», «Транскрипция получена», «перевод из словаря», «трактовка автора», «язык». Для явного заполнения полей используйте строки `**Написание:**`, `**Транскрипция:**`, `**Перевод из словаря:**`, `**Трактовка автора:**`, `**Язык:**`. Поле `**Транскрипция / форма разбора:**` также заполняет форму в таблице. Поле `**Предложенный перевод источника:**` показывается в колонке трактовки с пометкой «Чтение источника (независимо не проверено)», рядом с прежними чтениями; оно не заполняет словарный перевод. Если общая цитата разбирает соседние слова на разных языках, язык каждого слова следует задать своим полем `**Язык:**`.
