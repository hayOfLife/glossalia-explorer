# ADR-0014: Добавление новых транскрипций без обязательных уточнений

- Статус решения: Принято
- Дата: 11.10.2026
- Состояние реализации: правила работы ассистента при подготовке источников; автоматическое датирование исторических файлов в сборщике не вводится
- Связи: [правила добавления](../../DOCUMENTATION.md#добавление-новой-транскрипции), [формат разборов](0013-transcription-analysis-format.md), [инструкция сайта](../../../site/README.md), §transcriptionintake

## Контекст

Ранее при добавлении записи ассистент отдельно запрашивал время или оставлял назначение неизвестным. Автор попросил при отсутствии времени назначать текущее, самостоятельно распознавать один уже определяемый тип записи и сохранять сообщённые обстоятельства. Автор допускает самостоятельное предполагаемое назначение по этим обстоятельствам при уверенности выше 85% и не требует отдельного вопроса, поскольку назначение может быть неизвестно ему самому.

Обстоятельства уже встречаются в старых разборах под разными заголовками, иногда в назначении или вместе с толкованием. Дата сообщения, дата исторического получения и время разбора являются разными событиями. Отнесение записи к программоподобному типу по форме не устанавливает её перевод или происхождение.

## Варианты

Прежний порядок требовал уточнять время отдельным вопросом либо оставлять его неизвестным. Автор выбрал текущую отметку для нового поступления без времени и самостоятельное заполнение типа и допустимого назначения. Чтобы это не изменяло исторические сведения, правило применяется при приёме новой записи и сохраняет приоритет явно указанного источника.

## Решение

Порядок и ограничения определены в [стандарте](../../DOCUMENTATION.md#добавление-новой-транскрипции). Для новой транскрипции без времени и без другой явно указанной даты используется текущая отметка доверенных часов по Москве. Явные и относительные указания автора имеют приоритет; исторической дате без часа текущий час не приписывается. Существующие записи не датируются заново.

Ассистент сам указывает один из введённых типов по признакам исходной записи: `программа\команда\скрипт` для программоподобной последовательности с несколькими системными английскими словами или `молитва благодарения` для записи, основное содержание которой — благодарение и прославление Бога. Второй тип введён по указанию автора от 12.10.2026. При недостатке оснований используется `не определён`, без вопроса о типе; явно указанный автором тип имеет приоритет. Старые карточки при введении нового типа автоматически не пересматриваются. Сообщённые обстоятельства получают отдельный блок `Обстоятельства получения` между сведениями и назначением.

Уточнение автора от 12.10.2026: название этой категории в поле типа всегда полное — `программа\команда\скрипт`; сокращённое «скрипт» в сообщении автора не становится сокращённой меткой.

Явное назначение автора сохраняется. Выведенное из обстоятельств назначение допускается только при рабочей уверенности выше 85% и получает атрибуцию предположения ИИ. При недостатке оснований оно остаётся неизвестным без отдельного вопроса. Уверенность в цели не переносится в процент разбора и не объявляется измеренной точностью перевода.

## Последствия

Добавление записи требует меньше уточняющих вопросов и сохраняет контекст для последующего анализа. Неизвестное назначение допустимо. Пользовательский текст, назначение от автора и предполагаемая цель от ИИ остаются различимыми.

Правило текущего времени применяется ассистентом при новом поступлении, до обновления календаря. Изменение календарного генератора, которое незаметно приписывало бы сегодняшнюю дату историческим файлам без даты, этим решением не разрешено. Перенос обстоятельств старых записей и пересмотр их назначения не выполняются автоматически вместе с введением правила.

## Проверка и пересмотр

Проверяются непротиворечивость инструкции, приоритет источника, московский часовой пояс, отдельность обстоятельств, атрибуция предполагаемого назначения и отсутствие назначения неподтверждённого процента разбора. Для изменённых документов выполняются аудит в PowerShell 5.1 и 7 и проверка diff. При последующей интеграции записи проверяются её источник, карточка и календарь обычными узкими проверками проекта.

Решение пересматривается, если автор изменит часовой пояс, смысл времени по умолчанию, критерии типа или допустимость предполагаемого назначения.
