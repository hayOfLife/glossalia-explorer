# ADR-0010: Обращения к автору в скрытых чатах

- Статус решения: Принято
- Дата: 01.10.2026
- Состояние реализации: расширение API установлено на VPS 01.10.2026; локальный интерфейс проверен, статические файлы Tuqo обновляются отдельным архивом
- Связи: [сайт](../../../site/README.md), [скрытые комментарии](0009-hidden-comments.md), §authorinbox

## Контекст

Автор запросил обращения через `replyTo: "user_001"`, колокольчик с числом сообщений после входа владельца и отдельный просмотр каждого обращения с отметкой прочтения, ответом и удалением. Автор выбрал публикацию своих ответов в исходном чате от имени `user_001` и резерв имён `user_001`–`user_100`, чтобы посетители не могли получить их при генерации.

## Варианты

Для ответов рассматривались исходный чат и личное окно владельца. Выбран исходный чат. Для списка обращений допустимы отдельная страница и модальное окно; используется окно в существующей локальной панели управления.

## Решение

`user_001` — специальный адресат, а не идентификатор сообщения. Посетитель передаёт его в `replyTo` или выбирает «Написать автору» в скрытом интерфейсе. Сообщение остаётся в исходном чате. Ответ на сообщение автора также считается обращением к автору. Остальные ответы по идентификатору сообщения сохраняют прежнее поведение.

Случайные имена посетителей сохраняются. Диапазон `user_001`–`user_100` зарезервирован; никакое имя из него не назначается по токену посетителя. Сервер разрешает публиковать от имени `user_001` только ответ, созданный административным действием с действующей сессией владельца. Имя, поля запроса и локальный Origin сами по себе не дают этого права.

После входа в локальной панели колокольчик показывает число непросмотренных обращений из всех чатов. Окно выводит отдельные сообщения, позволяет явно отметить «Просмотрено», ответить в исходном чате или удалить сообщение. Открытие окна и ответ не отмечают сообщение автоматически. Правка просмотренного обращения делает его непросмотренным; удалённые сообщения в список не входят. Отметки сохраняются на сервере и переживают перезапуск.

Отметка прочтения передаёт время изменения показанной версии: если посетитель успел изменить сообщение, сервер требует обновить список. Очередь учитывает только действующие ключи; данные снятых с публикации чатов остаются в хранилище.

Версия 3 файла комментариев добавляет роль сообщения владельца и таблицу отметок прочтения. Версии 1 и 2 читаются без перезаписи и преобразуются при следующем успешном изменении. Идентификаторы сообщений, случайные имена версии 2 и файлы голосов сохраняются. Старый модуль версии 2 не читает файл версии 3, поэтому возврат прежнего кода после новых записей требует отдельной проверки совместимости.

## Последствия

Обращения и ответы остаются публичными для клиента API, знающего адрес чата. Административный список и отметки прочтения доступны только владельцу. Ответ владельца разрешён и при закрытой записи для посетителей, ограничен длиной, фильтром и проверкой повторов. Скрытые технические правила содержат пример запроса к автору. Статические файлы и модуль API обновляются отдельно; существующая установка пароля и маршрута Caddy используется повторно.

## Проверка и пересмотр

Проверяются запрет подделки владельца, резерв имён, прежние ответы, переход хранилища из версии 2, пагинация обращений между чатами, сохранение отметок, повторное уведомление после правки, удаление и ответы владельца. Для интерфейса проверяются число в колокольчике, отдельный просмотр, отмена ответа, истечение сессии и поздние ответы после закрытия окна. Итоги выполненных проверок и установки фиксируются в инструкции сайта.

Появление других владельцев или приватных сообщений потребует нового решения об аутентификации и доступе.
